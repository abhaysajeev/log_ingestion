================================================================================
 LOG INGESTION PLATFORM — DEPLOYMENT GUIDE
 Repo    : https://github.com/abhaysajeev/log_ingestion
 Host    : the old QA VPS (108.181.201.77, user administrator, sudo for docker)
 Domain  : logs.softlandindia.net
 Stack   : nginx · FastAPI · Redis · 2 workers · MongoDB · nightly backup
================================================================================

What it is
  Projects send logs to POST /ingest/batch with their own X-API-Key. Each
  project has its own dashboard at https://logs.softlandindia.net/p/<slug>/,
  opened by a link carrying that project's token, showing only its logs.
  Logs are kept LOG_RETENTION_DAYS (45) and then deleted by MongoDB itself.

Two ways to serve it — pick by what already holds ports 80/443 on the host:

  A. A reverse proxy already runs on the host
     (the old QA VPS: the host's own nginx owns 80 and 443)
     -> this stack listens on 127.0.0.1:8095 only; the host nginx gets one
        more site that forwards logs.softlandindia.net there and holds the
        certificate.  COMPOSE_FILE=docker-compose.yml:docker-compose.proxied.yml
  B. Nothing on 80/443
     -> this stack's nginx owns 80/443 and the certificate.
        COMPOSE_FILE=docker-compose.yml:docker-compose.https.yml

Resources: ~2.1 GB RAM at the configured limits (MongoDB 1.2 GB), ~150 MB of
disk per 100k logs a day, 45 days kept; nightly backups, 7 kept.

════════════════════════════════════════════════════════════════════════════════

  At the DNS provider for softlandindia.net add:

    Type  A
    Name  logs
    Value 108.181.201.77
    TTL   3600 (or Auto)

  Check it has spread (from any machine):   dig +short logs.softlandindia.net
  -> 108.181.201.77


════════════════════════════════════════════════════════════════════════════════
 STEP 2 — CODE AND SECRETS
════════════════════════════════════════════════════════════════════════════════

    cd ~
    git clone https://github.com/abhaysajeev/log_ingestion.git
    cd log_ingestion
    cp .env.example .env && chmod 600 .env
    nano .env
      MONGO_PASSWORD=<openssl rand -hex 16>
      ADMIN_TOKEN=<openssl rand -hex 32>
      LOG_RETENTION_DAYS=45
      COMPOSE_FILE=docker-compose.yml:docker-compose.proxied.yml     (way A)
      LOGS_LOCAL_PORT=8095                                            (way A; any free port)
      SMTP_*  (optional: leave SMTP_HOST empty for no alert e-mails)

  Check LOGS_LOCAL_PORT is free:   sudo ss -ltn | grep ':8095 '   (no output = free)

  Projects — one per sending system; prints its ingest key and dashboard link:

    python3 scripts/add_project.py byky-qa "BYKY QA" --profile byky \
        --base-url https://logs.softlandindia.net

  Keep the output: the ingest key goes to that project's server
  (BYKY: LOG_INGEST_KEY in the new QA VPS .env), the dashboard link to the
  people who read the logs. config/projects.json holds them; it is not in git.

 STEP 3 — START
════════════════════════════════════════════════════════════════════════════════

    sudo docker compose up -d --build
    sudo docker compose ps               # all Up; fastapi and mongodb (healthy)
    curl -s http://127.0.0.1:8095/health # way A: {"status":"ok",...}


════════════════════════════════════════════════════════════════════════════════
 STEP 4A — THE HOST'S NGINX (way A: the old QA VPS)
════════════════════════════════════════════════════════════════════════════════

  One new site; the existing sites are not touched.

    sudo nano /etc/nginx/sites-available/logs.softlandindia.net

    server {
        listen 80;
        listen [::]:80;
        server_name logs.softlandindia.net;
        client_max_body_size 8m;              # ingest batches
        location / {
            proxy_pass http://127.0.0.1:8095;
            proxy_set_header Host $host;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            proxy_read_timeout 60s;
        }
    }

    sudo ln -s /etc/nginx/sites-available/logs.softlandindia.net /etc/nginx/sites-enabled/
    sudo nginx -t && sudo systemctl reload nginx
    curl -s http://logs.softlandindia.net/health        # needs step 1's DNS
    sudo certbot --nginx -d logs.softlandindia.net      # certificate + HTTPS redirect

  (No certbot yet?  sudo apt install -y certbot python3-certbot-nginx)
  certbot renews on its own timer and reloads nginx.


════════════════════════════════════════════════════════════════════════════════
 STEP 4B — THIS STACK OWNS 80/443 (way B)
════════════════════════════════════════════════════════════════════════════════

    # COMPOSE_FILE=docker-compose.yml:docker-compose.https.yml in .env
    # nginx needs a certificate to start, and must be up to answer certbot --
    # so start with a temporary self-signed one:
    openssl req -x509 -nodes -days 1 -newkey rsa:2048 -subj "/CN=logs.softlandindia.net" \
      -keyout nginx/certs/privkey.pem -out nginx/certs/fullchain.pem
    sudo docker compose up -d
    sudo certbot certonly --webroot -w "$PWD/certbot/www" -d logs.softlandindia.net
    sudo cp /etc/letsencrypt/live/logs.softlandindia.net/{fullchain,privkey}.pem nginx/certs/
    sudo docker compose exec nginx nginx -s reload

  Renewal: put the same copy + reload in /etc/letsencrypt/renewal-hooks/deploy/logs.sh

 DAY TO DAY
════════════════════════════════════════════════════════════════════════════════

  Update:          git pull && sudo docker compose up -d --build
  New project:     python3 scripts/add_project.py <slug> "<Name>" [--profile byky]
                   sudo docker compose restart fastapi
  Own token:       python3 scripts/add_project.py <slug> --token <your-token>
                   sudo docker compose restart fastapi   (only the dashboard token
                   changes; the ingest key and the sending server stay as they are)
  Revoke a link:   python3 scripts/add_project.py <slug> --rotate
                   sudo docker compose restart fastapi   (old key and link stop)
  Retention:       LOG_RETENTION_DAYS in .env, then  sudo docker compose up -d fastapi
                   (changed in place; 0 keeps logs forever)
  Backups:         ./backups/logs-YYYY-MM-DD.archive.gz, newest 7 kept
  Restore:         sudo docker compose exec -T mongodb mongorestore -u admin -p "<MONGO_PASSWORD>" \
                     --authenticationDatabase admin --gzip --archive < backups/<file>
  Dead letters:    curl -H "X-Admin-Token: <ADMIN_TOKEN>" http://127.0.0.1:8095/admin/dlq
  Disk:            df -h /    and    sudo docker system df
